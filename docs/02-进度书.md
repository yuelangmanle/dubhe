## 4. 轮次记录

### W0 / Round 0 · 2026-10-29（立项）

**做了什么**

- 读完你的引擎开发书，确认技术路线可用，不改方向。
- 定名 **天枢 / Dubhe**（北斗第一星 + 中枢；Dubhe 是该星天文名）。
- 把 8 人团队的 63 周计划**作废重排**：现在是我写代码、你验证，里程碑按 Round 计（27–43 轮）。
- 首期范围收敛：**只做引擎 + CLI + 本地 HTTP，不做 UI**（UI 推迟到 M5）。
- 开源策略改为**全闭源**，但保留 Apache-2.0 / MIT 依赖（合法，只需保留声明；GPL 一律不进）。
- ADR-0005（引擎独立进程）**降级为 Proposed 并推迟到 M5**：首期单进程，避免过度设计。
- 新增 ADR-0007：AI 主开发 + 人类验证的协作模式。

**关键决策**

| # | 决策 | 依据 |
| --- | --- | --- |
| D1 | 名字：天枢 / Dubhe | 枢=调度中枢；Dubhe=北斗第一星，定方向=基准 |
| D2 | 我写全部代码，你做验证与拍板 | 你的选择 |
| D3 | 首期只做引擎 + CLI/HTTP | UI 不产生技术证据，且吃掉 2–3 个月 |
| D4 | 全闭源 | 先验证技术，M4 后再谈开源 |
| D5 | 单进程（不拆 IPC） | 首期只有自己用，拆了只增加调试成本 |
| D6 | C++20 内核，Python 只做工具 | 与上游生态同语言，hot path 零解释器开销 |

**下一轮（M0 Round 1）计划**

1. 工程骨架 + CMake 构建通过。
2. GGUF 解析器 + mmap 加载。
3. `dubhe inspect -m xxx.gguf` 打印模型元信息（层数、hidden、量化类型、tokenizer 类型）。
   → 这是第一轮验证点：**你只需要跑一条命令，把输出贴回来**。

**需要你**

- 回答 §3.3 的 B1–B4。
