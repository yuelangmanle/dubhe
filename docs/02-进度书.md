## 9. M0 实施记录（已完成）

环境：Apple M4 / 24 GB / macOS 27.0.1 / Apple clang 21。
测试模型：`Qwen2.5-0.5B-Instruct-Q4_K_M.gguf`（Qwen 官方发布，182 MB，
量化组合 F32+Q5_0+Q8_0+Q4_K+Q6_K —— 注意它不是"纯 Q4_K"，实际是混合量化）。

### M0 / Round 1 · 引擎骨架跑通

**交付**
- `engine/include/dubhe/dubhe.h` C ABI（版本 0.1.0）
- `engine/src/{gguf,quant,tokenizer,model,engine}.cpp`
- `cli/main.cpp`（inspect / run / chat / bench）
- `Makefile`（零外部依赖，clang++ -std=c++20）

**验证**
```
$ make && ./build/dubhe inspect <model>
架构 qwen2 · 24 层 · 896 维 · 14 头(KV 2) · 词表 151936 · ChatML
```

**踩到的坑（都是真实 bug，已修）**
1. `byte_to_char_` 对 161–255 的字节用了原始字节，而 GPT-2 的映射是"码位"，
   必须写出 UTF-8 编码（如 228 → `ä` = C3 A4）。否则中文全部切不开。
2. BPE 的初始符号必须是**字节**，不是 UTF-8 字符。原来按字符切，一个汉字被
   当成一个符号，merges 永远不命中。
3. `Makefile` 没有头文件依赖跟踪。改 `internal.h`（结构体加了成员）后只有部分
   `.o` 重编，`Model` 的布局在两个编译单元里不一致 → 一加载就段错误，
   堆栈还指向完全无关的 `build_byte_map`。已加 `-MMD -MP`。
4. KV cache 按训练上下文（32768）预分配 = 805 MB。改成从 1024 起按需翻倍。
5. `<|im_end|>` 被当成正文输出。EOS 判断必须在回调**之前**，且所有
   CONTROL/USER_DEFINED 类型的 token 都不能吐给用户。

**性能**：decode 7.7 tok/s（纯标量 f32 内核）。

### M0 / Round 2 · 内核 SIMD 化

**交付**
- `engine/src/quant_q8.cpp`：量化激活（Q8_0）+ ARM NEON 整数点积
- `tests/test_quant.cpp`：11 种类型的位解包自检 + 整数路径一致性自检
- `bench/matvec_bench.cpp`：按真实模型形状测各类型吞吐

**做法**：把激活也量化成 int8，两边都用 `vdotq_s32`（一条指令 16 次乘加），
K-quant 的 `-dmin·m` 偏置项拆成 `Σ q·a` 和 `Σ a` 两项分别算。

**验证**
```
$ ./build/test_quant
=== 内核位解包自检 ===  全部通过（相对误差 ≤ 1.6e-7）
=== 整数点积路径自检 === 全部通过（相对误差 ≤ 9.1e-4，属于激活量化噪声）
```

**效果**

| 形状 | 类型 | f32 | q8 | 加速 |
| --- | --- | --- | --- | --- |
| ffn_down 896×4864 | Q6_K | 0.669 ms | 0.178 ms | 3.75x |
| attn_q 896×896 | Q5_0 | 0.188 ms | 0.111 ms | 1.69x |
| out_w 151936×896 | Q8_0 | 15.115 ms | 10.468 ms | 1.44x |
| ffn_gate 4864×896 | Q5_0 | 0.657 ms | 0.412 ms | 1.59x |

**端到端**：7.7 → 20.0 tok/s（2.6x）。

**注意（重要）**：本机顺序读带宽实测只有 **17 GB/s**（真实 M4 应在 100 GB/s
量级），说明当前运行环境本身受限，绝对值不可作为真机结论。加速比可信。

**能力**

### 下一轮（Round 4）候选，按优先级

1. **Metal 后端**（GPU）。当前 Metal Toolchain 未安装，但可以绕开离线编译器：
   用 `MTLDevice.newLibraryWithSource` 在运行时编译 MSL。目标：把
   `out_w` 与 ffn 三件套搬到 GPU，M1 验收口径 B=1 decode ≥ llama.cpp 的 90%。
2. **prefill 批处理**（n_batch > 1）。现在 prefill 是一个 token 一个 token 算，
   长 prompt 首字延迟很难看。

4. **agent 循环**：多轮工具调用 + 计划-执行-反思，参考 Claude Code / opencode
   的工具协议。
5. **Android**：NDK 交叉编译 + NEON 已经是通的，缺 NPU（QNN/NeuroPilot）接入。
