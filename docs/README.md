## 写作规范

1. **Markdown 是源，docx 是产物。** 修改一律改 `.md`，需要排版版时用 `tools/docs/build_docx.sh` 生成，不要反向编辑 docx。
2. **表格优先于长段落。** 能被表格表达的（对比、矩阵、清单、任务）不要写成散文。
3. **每个数字必须有口径。** 写"快 30%"必须能回答：相对谁、什么设备、什么模型、什么量化、几次测量。
4. **不写形容词写事实。** 禁止"大幅提升""显著优化"；写"8 路 aggregate 从 272 提到 330 tok/s（+21%）"。
5. **中英文之间加空格**，术语首次出现给英文原词，之后统一用中文或缩写。
6. **路径用相对链接**，保证在 GitHub 上能点开。
7. 新增文档必须在本索引登记，否则视为未完成。

## 版本与评审

- 里程碑评审时冻结一版并打 tag：`docs/m0-review`、`docs/m1-review` …
- 冻结后的文档只允许"事实纠错"，实质变更写进下一个版本并在 §变更记录 留痕。
