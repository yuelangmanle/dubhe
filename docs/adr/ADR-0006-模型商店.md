# ADR-0006 · 模型商店：先做「可信清单 + 直接下载」，不做爬虫市场

- 状态：**提议中**（未实现）
- 日期：2026-11-18

## 背景

用户想在客户端里直接浏览、下载、导入模型，甚至把 HuggingFace / ModelScope /
Ollama 库解析成一个"模型商店"。

## 决定

分三层做，**顺序不能反**：

### 第一层：本地清单（已有）

`GET /api/models` 扫描 `--model-dir`，已经能报出路径、大小、量化、参数量、
是否有配套 mmproj、是不是 MLX。这一层不动。

### 第二层：可信清单 + 直接下载（建议先做这一层）

新增 `GET /api/store`，返回一份**我们自己维护的 JSON 清单**，不是实时爬虫：

```json
{
  "updated": "2026-11-18",
  "items": [
    {
      "id": "qwen35-8b-q4",
      "name": "Qwen3.5-8B Instruct",
      "params": 8.0,
      "quant": "Q4_K_M",
      "bytes": 5300000000,
      "arch": "qwen35",
      "url": "https://huggingface.co/.../Qwen3.5-8B-Instruct-Q4_K_M.gguf",
      "sha256": "...",
      "recommended": true,
      "note": "通用首选：中文好、支持工具调用"
    }
  ]
}
```

要点：

- **只放引擎真能加载的架构**（`llama` / `lfm2` / `lfm3` / `qwen35`）。
  清单里出现一个加载不了的模型，比商店空着更伤信任。
- 清单可以托管成一个静态 JSON（GitHub raw），客户端定时拉取，
  **不发版也能更新**；拉不到就用内置的兜底清单。
- 下载走 `curl -C -`（断点续传）+ 后台任务 + `/api/models/download` 查进度。
  不引 HTTP 客户端依赖。
- 下载完**校验 sha256**，不匹配就删掉并报错 —— 半个 GGUF 文件加载起来
  是崩溃，不是报错。

### 第三层：解析仓库网站（以后再说）

HuggingFace 有公开 API（`/api/models?search=`），ModelScope 也有。
但"把仓库解析成商店"有三个坑，不建议现在做：

1. 一个仓库里几十个量化文件，大小/精度/是否 mmproj 各不相同，
   选错就是下载 20GB 然后用不了；
2. 没有统一的架构字段，只能读 GGUF 头才知道能不能加载；
3. 社区改文件名、删文件是常态，清单会腐烂。

真要做，形态应该是"**搜索 + 在本地读 GGUF 头判断兼容性 + 只允许下载
能加载的**"，而不是直接把仓库列表铺出来。

## 导入

`POST /api/models/import { path }`：把用户指定的 .gguf **软链**到模型目录
（不复制，避免 5GB 文件翻倍占盘）。软链目标不存在时给明确报错。

## 后果

- 好处：下载路径可控、不会把用户带进"下了一个跑不了的模型"的坑。
- 代价：清单要人维护；新模型上架有延迟。
- 不做的事：不做自动爬虫商店、不做模型评分/评论、不做多源镜像切换。
